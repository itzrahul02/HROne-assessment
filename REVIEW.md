# REVIEW.md

Defects below are from the starter `app/main.py` (line numbers are the starter's). The helpers were rewritten: the old formulas could not be reused safely, and the endpoints now call the corrected ones.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (72-74) | Always returns 200. It never pings MongoDB, so a dead database still looks ready. | Stop MongoDB and `GET /health`. The starter returns 200; the runner expects 503. | Ping with `admin.command("ping")`. Any failure is 503 with `{"detail": ...}`. |
| 2 | module setup (22-23) | Falls back to a hard-coded `mongodb://localhost:27017` and `attendance_db`. The grader injects `MONGO_URI` / `MONGO_DB` and a hard-coded default can hide a missing variable. | Start with those variables unset. The starter silently connects to localhost. | Read both from the environment after `load_dotenv()`. Missing values raise at startup. `.env` does not override real variables. |
| 3 | `MongoClient` (22) | The client is not timezone-aware, so PyMongo hands back naive datetimes. Later IST math then treats UTC wall-clock as IST. | Read a seeded punch `2026-07-06T04:35:00Z` (10:05 IST). A naive value makes the shift comparison use 04:35 instead of 10:05. | `tz_aware=True` with UTC. Epoch milliseconds are converted only at the API boundary. |
| 4 | startup (whole file) | No indexes are created. Duplicate `emp_code` and duplicate `(emp_code, date)` are not enforced by the database, and the 100k-row list/analytics queries collection-scan. | Two parallel `POST /employees` with the same code can both return 201. `explain` on `/attendance` shows `COLLSCAN`. | Create unique and query indexes idempotently at startup (retried on the first request if MongoDB was down). |
| 5 | `compute_late_minutes` (33-37) | Shift start is built with `punch_in.replace(hour, minute)`, so the comparison uses the punch instant's own clock, not 09:30 IST on the attendance date. | Punch-in `2026-07-06T04:35:00Z` (10:05 IST, shift 09:30). Starter late minutes are 0; the rule says 35. | Build shift start as IST on the attendance date and compare instants. |
| 6 | `compute_late_minutes` (36-37) | It floors to whole minutes and then keeps the value only when `minutes > 10`. A punch 10 minutes and 1 second late floors to 10 and is treated as on time. | Shift 09:30, punch 09:40:01. Starter returns 0. R2 says 10. 09:40:00 correctly stays 0; 10:15:59 should be 45. | Late only when elapsed time is strictly more than 600 seconds. `late_minutes` is then `floor(elapsed / 60)` from shift start. |
| 7 | punch path (101) | Instants are not truncated to whole seconds before they are stored or used. `09:40:00.900` must count as `09:40:00`. | Send `punched_at` with 900 ms. The starter stores the fraction and can tip a boundary the wrong way. | Integer-divide epoch milliseconds by 1000 before converting. The truncated value is what is stored and returned. |
| 8 | `compute_work_hours` (40-41) | `round(..., 2)` is banker's rounding on a binary float, not half-up. | 3618 seconds is exactly 1.005 hours. The starter returns 1.00. R4 says 1.01. | Divide whole seconds with `Decimal` and `ROUND_HALF_UP`. |
| 9 | `compute_overtime` (44-47) | Three separate bugs: no 30-minute minimum (5 minutes of overtime is returned as 5); shift end is not placed on the next IST day for an overnight shift; the aware end minus a naive punch raises `TypeError`. | Punch out 5 minutes after 18:30. Starter would report 5, R3 says 0. Calling the helper with a naive punch crashes. Overnight 22:00-06:00, out at 06:40 next day, is not 40. | Both instants are UTC. Overnight shift end is attendance date + 1 at `shift_end` IST. Return the floored minutes only when they are >= 30. |
| 10 | `create_employee` (77-85) | Check-then-insert loses the race. `created_at` is naive local `datetime.now()` and is returned as a datetime (JSON string), not epoch ms. `emp_code`, email, and `shift_start == shift_end` are not validated. | Parallel creates with one new `emp_code` can both be 201. Response `created_at` is a string. `EMP1`, a bad email, or equal shifts are accepted. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. Pydantic enforces the contract. `created_at` is UTC and serialized as epoch ms. |
| 11 | `list_employees` (88-96) | `skip = page * page_size` skips the first page. `total` ignores the department filter. Results are not sorted by `emp_code`. `page_size` is not capped. Datetimes leak out. | `page=1&page_size=20` omits the first 20 employees. Filter `department=Engineering` and `total` is still the whole collection. Page 1 is not in `emp_code` order. | Skip `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, cap `page_size` at 100, serialize `created_at`. |
| 12 | `punch_in` (99-121) | `fromtimestamp` is local time, so the attendance date is not the IST date and overnight shifts are ignored. The duplicate check is check-then-insert. An unknown employee raises `KeyError` (500) instead of 404. The body accepts any status and a seconds-sized timestamp. The response adds `id` and leaves datetimes unconverted. | Punch `2026-07-07T00:00:00+05:30` for shift 22:00-06:00 must land on the previous date; the starter uses the machine timezone. Unknown `emp_code` is 500. Response contains `id`. Two parallel punch-ins can both insert. `punched_at: 1700000000` is accepted. | R1 date, R2 late, truncate to seconds, 404 if the employee is missing, 422 from the schema, insert straight away and map `DuplicateKeyError` to 409. Response is the natural key only, with epoch ms. |
| 13 | `list_attendance` (124-150) | Loads the whole collection and sorts it in Python. Sort is date descending only, not then `emp_code` ascending. Each row gains `id`. `date_from > date_to` is not 422. Legacy documents omit `half_day` and `history`, and punches come back as datetimes rather than epoch ms. | On ~100k rows this is slow and memory-heavy. Two rows on the same date are not ordered by `emp_code`. Seeded `EMP0002` / `2026-07-14` has no `half_day` or `history` in the JSON. `date_from=2026-07-10&date_to=2026-07-01` returns 200. | Indexed `find` with hint, sort, skip, and limit. Reject an inverted range and a bad status. Serialize every record, defaulting missing `half_day` to false and missing `history` to `[]`. |

Looked at, and not a defect:

- `load_dotenv()` without `override=True`. Existing environment variables already win, which is what the runner requires.
- Punch-in leaving `history` empty, `overtime_minutes` at 0, `half_day` false, and `work_hours` null. Those defaults match the contract; punch-in and punch-out must not write history.
- Default `status` of `PRESENT`.
- Inclusive `$gte` / `$lte` on `date_from` / `date_to`. The bug was loading every match into memory, not the predicate.
